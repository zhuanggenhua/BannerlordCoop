# 双人测试包（局域网优先）

双方必须安装相同游戏版本和同一份新测试包。具体代码提交、游戏版本和各 DLL 的 SHA256/MVID 见 manifest.json。本包不包含游戏资源，不修改已有存档，不附带旧 LocalA 示例存档。

1. 退出骑砍 2，双方解压完整 ZIP，运行 `0-Install.cmd`。旧 Coop 将完整移到游戏根目录的 `CoopDemoBackups`，不删除。
2. A 运行 `1-HostNew.cmd`，在主菜单点击 **创建联机房间**，按原生流程创建新角色和战役。进入大地图后记下 A 电脑的局域网 IPv4 地址，可在命令提示符运行 `ipconfig` 查看。
3. B 运行 `2-Guest.cmd`，在主菜单点击 **加入联机房间**，选择 Direct 页签，输入 A 的局域网 IPv4 地址。端口默认 `4200`；只有 A 修改过端口时才填写 `地址:端口`。等待存档快照加载后进入同一世界。
4. 优先让两台电脑连接同一个路由器/局域网，第一次连接时允许 Windows 防火墙提示中的 Bannerlord 网络访问。不要用 `127.0.0.1` 或 `localhost` 测远端玩家。
5. 局域网连接通过后，再用 Steam 好友邀请测试外网路径：双方登录各自 Steam、互为好友并开启游戏内 Steam 覆盖；A 在地图按 **Esc → 邀请 Steam 好友**，B 接受邀请。
6. 继续已有战役：A 使用 `3-HostSave.cmd`，输入同一 Steam 房主身份创建的联机存档名，不含 `.sav`；必须保留对应 `.sav` 和 `.json`。脚本不会修改存档身份。旧测试包的 LocalA/testclient1 存档不能当作真实 Steam 身份存档直接复用。

本包默认验证局域网直接 UDP 连接，也保留现有 Steam 大厅与 P2P 隧道。两者使用相同的游戏同步逻辑，但网络路径不同。测试时记录选择的是 Direct 还是 Steam。包不使用 `/platformId` 测试身份、不启动独立游戏服务器、不创建本地回环客户端。动态战役权威的已有验收范围和失败场景保持原记录；加入世界不代表整个 P2P 已完成。

## 请记录两项体验

- **移动响应：** 双方分别走动、点击远处、快速改变方向后停下，留意远端位置多久开始响应、是否倒退或持续抖动。
- **地图流畅度：** 记录启动前菜单/地图 FPS、进图后 FPS、大约是否仍是 2 倍速、是否发生长卡顿。性能日志只关闭了高频对象创建/销毁成功栈，不会改变游戏模拟速度。

若 LAN 直连超时，保留两端诊断包，并附两台机器的局域网 IPv4、是否同一路由器、测试时间和错误提示；不要发送公网 IP 或 Steam 账号敏感信息。

## 报错怎么反馈

出现卡住、断线、不同步或异常时，双方都运行 `5-Export.cmd`。可以在游戏运行时采集；原始日志可能继续写入，因此证据明确标记“运行中副本”，不宣称多个文件是原子快照。采集后先检查个人信息，再把诊断 ZIP 手动发送给开发者，脚本不会自动上传。

ZIP 包含中文摘要、完整原始日志、运行 PID、采集时间、包提交版本、包清单记录的 DLL MVID 和 SHA256。MVID 属于包清单，不冒充已加载进程的实测身份。原始异常、堆栈和失败记录保持原文，摘要的分类仅为线索，不能凭关键词判断根因。

发送 ZIP 时另外说明：谁是房主、谁出问题、当时在地图还是战斗、操作步骤、出现时间、大约 FPS；不要只截最后一行。若卡顿仍在，请注明运行速度倍率。 `4-Logs.cmd` 可以打开原始日志目录。工具不导出进程完整启动命令行或密码，不清除日志。

本轮用户正在游戏中时不会自动替换 Mod、重启游戏或启动验收。安装必须先退出游戏。
