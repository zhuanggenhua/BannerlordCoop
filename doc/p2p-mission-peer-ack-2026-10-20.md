## Diagnostic interpretation

- `Room peer disconnected before publish` records `Reason`, `SocketErrorCode`, peer ID, process-local reference identity, endpoint/state, mapped controller when available, current lease and transport reference. It runs before existing subscribers clear mappings. It does not replace or deduplicate disconnect events.
- `Freeze ACK send stage`: `send-call`, `send-call-returned`, then `flush-call-returned-delivery-unconfirmed`. Captured ticks, movement party count/hash and lease/sequence identify the checkpoint. `CoopClient.DescribeRoomPeers()` snapshots the real connected peers of the room transport without connecting, sending or flushing. Non-CoopClient and disposed transports say `Unavailable`; an observed empty set says `connected=0`. Snapshot membership can change before the send and is not a recipient or delivery receipt.
- `Freeze ACK receive stage`: `ingress`, `game-thread`, the first `rejected-*` predicate, or `qualified-current-peer`. Non-peer sources are logged and rejected at ingress. Individual checkpoint prepare/apply/install/commit failures are identified while preserving every original predicate's order and return value. Existing checkpoint rejection and exception logging remain.
- Reference hashes are only meaningful within one process/run and are not globally unique IDs. Endpoint/peer ID/reference together help identify replacement callbacks. No payloads, passwords, checkpoint contents or `AdditionalData` are logged. These are lifecycle/handoff observations, not per-Tick logging.

The only production `new PlayerDisconnected` source found in this repository is still `CoopServer.OnPeerDisconnected`; `LiteNetP2PClient.OnPeerDisconnected` removes its Mission peer rather than publishing that room event.
