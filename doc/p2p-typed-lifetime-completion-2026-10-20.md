## Adapter

CampaignLifetimeCompletion is a session-container service. Its Army scope nests across MobileParty.Army, Army.OnRemovePartyInternal and Army.DisperseInternal. Only a successful terminal native disperse certifies a duplicate in the same still-current scope. The outermost Harmony finalizer runs after every ordinary postfix and publishes the unchanged InstanceDestroyed once. ArmyRegistry only removes its eager generic destroy binding. Constructors and typed cleanup remain intact. Standalone disperse does not acquire an invented null objective; native FinishArmyObjective still moves and clears the objective in the outer removal case, with the original field message before destroy.

The MapEvent scope captures an actual first native finalization's participant identities. MobilePartyRegistry defers only the already-registered PartyBase of a garrison in that exact graph. It keeps the original roster flush/destruction and all native local destruction. The MapEvent finalizer releases held PartyBases through the original handler only after the complete original FinalizeEventAux and its ordinary postfix/subscribers. This does not make generic graph destruction own PartyBase or manufacture missing identities. A thrown original/postfix, incomplete original, changed lease or failed release leaves a faulted session drain.

CampaignAsyncTaskDrain checks the completion service both before and after native WaitAsyncTasks. Every existing caller of that drain therefore refuses unresolved lifetime state. The root integrator must register CampaignLifetimeCompletionModule in GameInterfaceModule before deployment. The production service must not silently be absent; direct legacy test constructors retain optional arguments.

## Confirmed-writer role and message seam

Additional four-point review was supplied to root before implementation. Existing Army prefixes publish original join/remove/Kingdom/objective messages, and typed receive helpers apply membership and tracking without re-running native destruction. Static process-role checks blocked B's confirmed writer while permitting A's observer to create extra world effects. These need qualification and receive routing adapters; the original native algorithms and message fields remain usable. Invariants at risk are current-writer-only side effects, Epoch rejection, no receive republish, unchanged legacy local bootstrap, ordered field-before-destroy and original UI behavior. Regression cases cover A observer/B writer, frozen/paused/unknown leases, AllowedThread receive, actual sender serialization and actual relay duplicate/stale-Epoch rejection.

Army prefixes now use the existing CampaignSimulationAuthorityPolicy. Original receive application is AllowedThread-scoped on the game queue for either process role when a confirmed session exists; the existing authority relay owns forwarding once. Unknown legacy handler branches retain their prior local behavior. Four original Army message types add only ICampaignAuthorityScopedMessage, without modifying Protobuf fields, allowing the existing sender/relay to fence them by lease/Epoch/sequence.

The Disperse adapter explicitly refuses a non-writer original call while allowing received originals to stand down. An unknown bootstrap has no typed lease scope; its finalizer falls back to the exact original LifetimePatches<Army>.DestroyPostfix. Controlled actual-engine tests exercise ListenAuthority and DedicatedAuthority bootstrap, plus unknown replica and confirmed observer/frozen/paused rejection. The existing message infrastructure rejects unwrapped marker messages even when the sender has no confirmed lease. Therefore this preserves unknown-bootstrap local behavior, and does not claim support for an active legacy network session without a confirmed lease or weaken PacketHandler validation.

The three additionally approved MapEvent entrypoints (FinalizeEventAux, CommitCalculatedMapEventResults, Update) use the existing world-writer policy. Their contribution/reward/repair algorithms remain unchanged; role tests invoke the actual prefixes. Other static role guards, notably OnBattleWon, BattleState and Initialize, are intentionally still recorded as unconverted follow-up scope rather than silently swept. A complete B native day remains unaccepted until all original NPC battle/economic behavior is verified.
