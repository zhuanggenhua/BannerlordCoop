# Native Mission exact health no-op adapter

Base `1cb8a5329dfcce95b1a794f198fbecf78bafb95f`. This adapts an observed redundant native setter, not changed-health permission, damage routing or battle-result synchronization.

## Four-point change boundary

1. Original Hero HP AutoSync and owned-health request handling already replicate real health changes. CoopAgentOrigin protects owned battle health and finalization. Mission03 B's native PartyAgentOrigin teardown instead calls the ordinary HP setter with local MainHero Player old/requested/final/post100, originalRan=true, no exception, paused epoch6; original managed-write ERR is retained. These mature systems remain unchanged.
2. Actual1.4.8 CampaignSystem SHA256`1f8e33e2ed73e6ec653d7629180afb70649ddc6e5bd1657a802a264efda1c3ae` setter IL0000..0009 reads _health, compares the raw requested int and immediately returns for equality. No assignment, clamp, MaxHitPoints lookup, roster notification or wounded event occurs on that path. Getter only reads _health. A separate bool prefix suffices; no core/generator/request rewrite is needed.
3. The new priority600 prefix only returns false for initialized GameThread, a current Mission, remote-replica local MainHero, exact old==current argument, denied ordinary-original allowance, known confirmed lease with no local writer, and existing health-ownership approval. Null/offthread/uninitialized/outside-Mission/other-Hero/unknown-lease/writer/host/approved receive/changed value follow their original path. Confirmed lease and original-call policy are checked before reading Campaign, Game, PlayerTroop or MainHero; incomplete bootstrap or a non-CharacterObject player never reaches MainHero/health ownership. It never clamps or edits value/HP, publishes a request, permits another setter, or opens an original-call scope. Higher-priority argument changes are read live at600, rather than trusting entry diagnostics at800.
4. Regression must cover actual generated ref prefix and actual no-ref health request, native equality IL, priority order/live argument, owned/unowned real changes, approved receive, skipped-original diagnostic finalization, original exception identity, fixture cleanup and all excluded roles/states. Final integrated dual-game Mission validation remains mandatory; offline checks cannot establish native acceptance.
