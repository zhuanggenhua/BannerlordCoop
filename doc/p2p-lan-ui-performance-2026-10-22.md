# 局域网联机入口与地图卡顿整改（2026-10-22）

## 本次修改依据

1. 原主菜单复用 `InitialStateOption` 注册开房和加入入口；Release 注册两个入口，DEBUG 却根据 `/listenhost`、`/client` 只注册一个，所以同一份测试包在两种启动脚本下展示不同选项。原有 `CoopConnectionUI` 已提供直接连接入口，底层 LiteNetLib UDP 和移动预测继续复用。
2. 不需要重写 UI 框架、网络传输或移动算法。DEBUG 菜单分支的源码证实入口被启动角色条件合并；单人 ListenHost 可以由既有 `StartAsListenHost()` 从主菜单启动。移动机制保留用户现有的预测、权威校正、序列化和发送节流。
3. 创建房间现在使用原生单进程 ListenHost 新战役流程；加入仍调用现有 `JoinWindow()`。六种高频对象的 Registry 仍分配句柄、发布创建/销毁消息、应用回调和记录错误，关闭的只是成功生命周期事件的 DEBUG 逐对象日志。排查时可临时重新启用单个 Registry 的 `Debug`。
4. `NetworkConfig` 的 25ms 轮询同时控制直接 UDP 与 Steam 隧道的收包、合并消息刷出及过载检查间隔。旧双进程移动观测显示远端模型/视觉出现在后续 12–55ms 的采样帧，不能从中把全部等待归因给网络。将直接 UDP 轮询缩短到 10ms，是针对现有 25ms 队列等待的有限适配；Steam 隧道保持 25ms，避免无差别提高轮询负担。
5. 必须由用户在两台机器上以直接 LAN 地址验证双向移动、急停、转向、招募/世界同步和持续运行。观察器须同时记录命令采用、下一 GameThread 模型帧、远端模型/视觉帧和 Epoch；不得把打开加入界面、连接成功或主观感觉当作延迟 PASS。

网络改动的边界：原始 LiteNetLib Poller、ReliableOrdered 消息格式与收发顺序保持不变；现有 `INetworkConfig` 只有一个轮询间隔属性，没有按传输方式选择的独立适配器，所以用 `IsTunneled` 在现有配置中区分两个时延档。回归需验证两种间隔值且消息顺序/对象生命周期不变；轮询线程负载和实测 LAN RTT 由双机运行确认。

## 卡顿证据与改动范围

用户上一轮的 2 倍速地图采样保存于 `.mcp-local/manual-performance-20261021-205637/sampling.json`，样本时长 8.04 秒：总 CPU 13.3%，单个最忙线程约占单核 88.7%，GPU 18%，同步日志写入约 51,550 字节/秒。对应日志 SHA256 为 `27ad6597eac8c3d6c18f8b855a4f4299698eb497bba8da412fba633242fb4ece`；尾部 1,200 行中 1,152 行是自动 Registry 创建时捕获的调用栈。日志使用 `SizeLimitedFileSink`，每个事件同步 `Flush`。记录还显示地图 Encounter 周期内 `MobileParty`、`MapEvent`、`MapEventParty`、`TroopRoster`、`ItemRoster` 和地图战斗视觉对象频繁创建或销毁。

因此关闭上述六个 Registry 的成功创建/销毁 DEBUG 日志，避免在游戏线程重复格式化栈并同步落盘；保留 Error、Warning、自动同步和对象生命周期功能。该证据足以支持这项明确的减负，但没有修改后的帧时间样本，不能据此宣称卡顿已经消失。

直接 UDP 从 25ms 改为 10ms，相当于把该轮询从最多每秒 40 次提高到 100 次。它能缩短消息在网络轮询队列内等待的上界，同时增加后台网络线程活动；主游戏线程帧时间仍是端到端响应的重要边界。Steam 隧道仍为每秒最多 40 次。

## 使用方式

- 主菜单始终显示“创建联机房间”和“加入联机房间”。创建项直接启动当前进程中的 ListenHost 新 Sandbox 战役，不需要额外的 Bannerlord 进程。
- 两台机器在同一局域网时，房主查本机局域网 IPv4；好友打开加入界面，使用房主局域网 IPv4 和默认端口 `4200` 直接连接。Steam 邀请保留给 Steam 房间，不作为局域网延迟基线。
- 局域网直连超时应保留两端中文诊断导出、游戏版本、PID 和网络地址。不得仅凭测试包 UI 出现就判断双方可达。

## 未验证事项

本修改没有运行 Bannerlord 或自动化游戏测试。自动化回归应覆盖 Direct=10ms、tunneled=25ms 两种轮询配置，并保证消息序列、可靠有序交付及对象生命周期不变。局域网 RTT、双客户端移动体感、断线重连、不同 Windows 防火墙/路由环境以及整改后的 FPS/帧时间，都等待用户和好友实测。日志证据来自旧运行提交 `7d5edd4259845d371ae2a0f3cb6de6a69a69b073`，用于定位修改动机，不是新版本验收结果。
