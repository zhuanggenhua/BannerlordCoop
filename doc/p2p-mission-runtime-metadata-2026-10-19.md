# Native Mission runtime metadata collection

Base: `5a3bc8f4cc032171da8577411b605dff607f02fc`. This changes only the QA Mission driver, its offline tests and this note. It does not change game code, MCP transport or timeouts.

## Four-point boundary

1. The existing driver launches exactly two native game processes, joins once, compares their actual loaded assemblies/build and then validates world/Mission/pause/resume. `pollReadOnly` already carries a single 30-second convergence deadline and forbids mutations inside a read scope. These behaviours are retained.
2. Mission04 run `01bd758941544f34a31834d758d4cc75` failed before any feature. A PID19736 returned complete status; B PID23240 remained alive but its current `get_run` status was null with `operation_cancelled`, `outcomeUncertain=false`. The driver directly dereferenced `row.status.loadedAssemblies` outside its read-only poll. Source chain: `RunOrchestrator.GetAsync` refreshes both peers; `RefreshAsync` supplies a linked three-second token; `LiveTestPipeClient.SendAsync` maps its cancellation into a structured failure; `ApplyStatus` deliberately clears failed status. Earlier ready evidence does not guarantee the next status call succeeds. The exact native cause of this one three-second delay was not observed. A QA collection adapter suffices; no core rewrite is justified.
3. The adapter retries only missing current metadata or an explicit non-uncertain readonly cancellation, while launch identity, liveness and every available metadata field remain valid. It pins PID/starttime/role/platform/run-token from the launch response, actual host build and loaded MVIDs as comparison expectations, and Coop MVID against preflight. Acceptance requires both complete error-free statuses from one new `get_run`, matching those expectations. Expectations are never substituted for missing current status. A mismatched available field, dead process, changed identity, unknown error, malformed assembly data or uncertain cancellation fails immediately, even if another peer is pending and a later response would be favourable.
4. Tests cover cancelled/missing-to-complete reads, missing fields, no cross-read pair assembly, fatal identity/liveness/errors/build/MVID corruption, the existing mutation guard, late results and a persistent pending sequence. All attempts share the original 30-second deadline; no retry resets it, no timeout is increased and no mutation is replayed. The original assembly comparison is strengthened to require the six actual runtime assemblies with unique names and valid MVIDs.
